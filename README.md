# 团队管理交互 Demo

这是一个不依赖构建工具的静态交互原型，包含：

- 按参考结构重排后的会员、积分、席位瓷片区
- 成员管理（操作区仅保留删除）
- 积分管理 Tab、三种积分的已分配 / 未分配额度与积分流水入口；全局不使用进度条
- 默认只读；点击“积分调配”进入单个成员的编辑模式，调整三类额度后“确认”提交，“取消”放弃草稿
- 分配余额校验、缺额提示、可回收成员高亮与受限回收流程
- 已消耗积分分类明细，以及购买积分进入团队待分配池的模拟流程
- 团队审批与新成员按每席位额度自动发放（余额不足时按剩余量发放）
- 删除成员自动回收未使用积分、邀请成员、复制与轻提示交互

Demo 中的积分遵循守恒关系：

`剩余总积分 = 已分配积分 + 未分配积分`

已分配积分为所有成员尚未使用的余额；未分配积分为团队当前可分配余额。每种积分均遵循同样的公式，分配和回收只转移余额，不改变剩余总量。

直接打开 `team-management-demo.html` 即可体验。该单文件已内嵌全部样式和脚本，无外部依赖，默认进入成员管理；适合离线使用或分享，避免独立脚本缓存导致预览旧版。

本地预览：

```bash
python3 -m http.server 4173 --directory team-management-demo
```

然后访问 `http://localhost:4173`。

## 固定公网预览

发布入口：[团队管理 Demo](https://team-management-demo.xiaoyuflight.chatgpt.site)

该站点使用 Sites 在线托管，目标访问范围为任何持有链接的人，不依赖本机或局域网。
后续修改 `index.html`、`styles.css`、`app.js` 后，执行 `node build.mjs`，再通过 Sites 发布到 `.openai/hosting.json` 记录的同一站点。发布成功后，访问原链接或刷新即可看到最新版本，无需更换链接。

`build.mjs` 会同步生成 `public/index.html` 和离线单文件，避免在线、离线版本不一致。在线版本只托管 `public/`，不包含本地工作区。

这是前端交互演示：各浏览器的成员和积分操作独立模拟，刷新后恢复初始数据，不连接真实团队账户。
